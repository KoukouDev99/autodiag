# PRINCIPE D'ARCHITECTURE (NON NÉGOCIABLE)
Hiérarchie stricte, du plus fort au plus faible :
1. RÈGLES DE SÉCURITÉ (freins, direction, airbag, fuite carburant) → arrêt dur,
   l'IA ne peut ni contourner ni adoucir.
2. MOTEUR DE RÈGLES DB (DiagnosticEngine.evaluate) → produit le fault_code
   et le score de confiance. Seule source d'autorité pour un diagnostic.
3. IA DE SORTIE → reformule/explique le résultat du moteur, sans jamais
   altérer le fault_code ni le score.
4. IA D'ENTRÉE → normalise le texte libre utilisateur vers un symptom_id
   (propose, ne décide pas ; validation par whitelist DB).
5. IA DE FALLBACK → uniquement si le moteur ne renvoie AUCUN match.
   Sortie étiquetée "NON VÉRIFIÉ — consulter un professionnel".
   Ne produit JAMAIS de fault_code ni de score.

Règle d'or : l'objet affiché à l'utilisateur provient TOUJOURS d'un résultat
produit par evaluate(...). L'IA ne fait que le mettre en forme.

## 3. Orchestrateur hybride — backend/src/diagnostic/orchestrator.js

Fonction principale : async runDiagnostic(input) → DiagnosticResult
Étapes OBLIGATOIRES dans cet ordre :
1. Résoudre symptomId :
   - si input.symptomId fourni → l'utiliser
   - sinon → aiEntry.normalizeSymptom(input.symptomText)
   - si résolution échoue → retourner { source:'rules', faultCode:null,
     needsProfessional:true, reason:'symptom_unresolved' }
2. Vérifier règle de sécurité (table safety_rules ou constante interne) :
   - si match → retourner immédiatement safetyAlert=true, source:'rules',
     needsProfessional=true. L'IA de sortie est appelée UNIQUEMENT pour
     reformuler, jamais pour atténuer.
3. Appeler DiagnosticEngine.evaluate(sessionId, ...) → rulesResult
4. Si rulesResult.faultCode != null ET confidence >= SEUIL_CONFIANCE_MIN :
   - explication = aiExplain.explainResult(rulesResult)
   - retourner source:'rules', candidates=rulesResult.candidates
5. Si rulesResult.faultCode != null ET confidence < SEUIL_CONFIANCE_MIN :
   - retourner source:'rules', faultCode, confidence,
     needsProfessional=true, explanation="confiance insuffisante"
6. Si rulesResult.faultCode == null (aucun match DB) :
   - fallback = aiFallback.suggestFallback(...)
   - retourner source:'ai_fallback_unverified', faultCode:null,
     needsProfessional:true, hypotheses étiquetées non vérifiées

Interdictions absolues dans orchestrator.js :
- Ne JAMAIS laisser l'IA écrire dans diagnostic_sessions ou session_answers
- Ne JAMAIS utiliser une sortie IA pour décider de l'arrêt précoce
- Ne JAMAIS exposer un fault_code non présent dans la table faults
- Ne JAMAIS court-circuiter la garde Migration 004 (0 réponse ≠ completed)
